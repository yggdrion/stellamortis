# M23 Inventory, loot and saves

Status: built (2026-11-16, v0.24.0), play-test pending (`docs/PLAYTEST.md`).

## Goal

Killing things pays. Enemies burst into loot that is worth running for, gear changes how a fight goes, the inventory is pleasant to manage, and the world and the character survive a restart.

## Depends on

M22 (kinds, boss site, world flags, cleared camps, the elite camp). File level detail was written against the code of 2026-11-16 (M22 built, `Net.PROTOCOL_VERSION` 28, `World.POOL` 20); where a name below no longer exists, the code is right.

## Design

- `ItemDef` (resource, `game/data/items/`): id, name, kind (weapon, shield, ranged, armor piece, trinket, material, bolt, consumable), slot, stack size, rarity, weight, stats (damage, defense, stamina), icon, model.
- Inventory lives on the server per player: a bag of 32 cells and gear slots apart from it, so worn gear takes no bag space: main hand, off hand, ranged, helm, chest, legs, cape, two trinkets, bolts. Clients send intents (`move`, `split`, `equip`, `drop`, `sort`, `store_matching`), the server answers with deltas; a snapshot at join.
- Rolled back: only the equipped ids that combat needs (main hand, off hand, ranged, armor total as one small int each), in a packed group. `Combat` reads damage and defense from them.
- Drops are world objects: server-side entries (id, item, count, position), sent as deltas; clients animate them. Pickup is a server decision on an intent or on walking over (materials auto pick up).
- Loot tables per `EnemyDef` and per chest, as data.
- Death: the bag (not the worn gear) stays in a grave at the place of death; the grave is a world object, saved, and only its owner can open it for 10 minutes.
- Character file on the client: `user://characters/<name>.json` (player ID, inventory, gear; level and perks from M57). Sent with hello; the server uses it as is. The server sends the character back on change and the client writes it (temp file, rename), so a crash loses seconds, not the session.
- World file on the server: `user://worlds/<name>.json` (seed, flags, cleared camps with times, world objects). Autosave every few minutes and on exit.
- `Settings` gets a random player ID.

## Code as it is (what the tasks hook into)

- Players: `SimPlayer` (`sim/sim_player.gd`). Rolled back state is `STATE`, packed into `MOTION`, `COMBAT`, `BOLTS` (`net_motion`, `net_combat`, `net_bolts`; `SYNCED`). `weapon` is `Weapon.SWORD` or `CROSSBOW`, read from `PlayerControls.weapon` (keys 1 and 2, `Controls`). Damage a player deals: `AttackDef.damage` in `_strike` (melee) and `Tuning` `bolt_damage_min/max` in `_shoot` (bolts, stored per bolt in `bolt_damage`). Damage a player takes: `def.damage` in `_take`; a block keeps `Tuning.block_reduction`, stamina cost `block_stamina`. Enemy hits go through `Enemy.take_hit(amount, from, knockback, flinch)`, the one signature.
- Enemies die at `Enemy.take_hit` (`action = DOWN`). The server sees it in `Spawner._tend` (the first tick a member is `DOWN` goes into `_dead[unit][member]`) and the boss in `Encounter._rollback_tick` (phase `BOSS` to `CLEARED`). `Spawner.update` runs after every rollback tick (`NetworkRollback.after_process_tick`), also in resimulated ticks, and decides every `PERIOD` 6 ticks: nothing it does may happen twice when a tick is replayed (keep memory that is not rolled back, as `_dead` does).
- Camps: `Spawner._units` (camps of `SpawnPoint`s, a pure function of realm and seed), `_ids` (`[realm id, camp id]` per unit, stable for one seed), `_cleared_until` (unit to the tick it reopens; ticks restart with the server, so a save keeps seconds left), `cleared_left(ids, until, realm, tick)` builds the seconds-left dictionary for the debug map. The elite camp is the recipe in `Spawner.RECIPES` that holds `barrow_elite`.
- World flags: `World.flags()` reads `Encounter.phase == CLEARED` (`RealmDef.boss_flag`); `Encounter.flag_set(node, flag)` is what gates use (`Portal.needs_flag`). The Warden's slot is `Pool0` (`Encounter.boss`); a cleared fight shows its corpse (`Action.DOWN`).
- Net: `net/net.gd` holds every RPC (`hello(version, name)`, `world(seed, name)`, `world_ready`, `notice`, `request_cleared_camps`). `GameServer._on_hello` (`net/game_server.gd`) admits, sends `world`, waits for `world_ready` and clock sync, then `World.spawn_player`. `GameClient` (`client/game_client.gd`) sends hello when connected (`_watch_connection`) and builds the world on `world_received`. `GameServer.world_seed` and `world_name` come from `--seed` and `--world` (`boot/main.gd`); the name is stored but not used yet. Solo (`--solo`) is a server process the client spawns; it quits when its player leaves (`GameServer._remove_player` and the join timeouts call `get_tree().quit`).
- Wire: `net/wire.gd` `_fill()` has a serializer per rolled back property name; `tests/wire_test.gd` fails for a missing one and checks the 508 byte limit.
- UI: `Menus.theme()` (Cinzel, Alegreya), `Hud` (`Hud.notice(text)` toasts, `_show_encounter` boss bar), `PauseMenu`, `MainMenu` (buttons for solo, host, join, settings), `Controls` (an action map of key lists, F-keys, M for the map), `Settings` (`user://settings.cfg` via `Graphics.SETTINGS`). Sounds: `Sounds.library` names, Kenney files in `assets/sounds/kenney/`.
- Client views of the world: `Arena.add_site_looks` (M22 task 4) shows how a client only look is built from seeded positions under a realm's place node; `ObjectsView` below follows it.
- Assets already vendored for loot: Quaternius props `Chest_Wood`, `Crate_Wooden`, `Barrel`, `Sword_Bronze`, `Axe_Bronze`, `Shield_Wooden`, `Torch_Metal`; look at `assets/quaternius/props/` before adding any.

## Tasks

### 1. Items, inventory, equipment (Opus)

Files: new `sim/item_def.gd`, `sim/items.gd`, `sim/inventory.gd`, `sim/loadout.gd`, `data/items/*.tres`, `net/inventories.gd` (server), `net/net.gd`, `net/game_server.gd`, `net/wire.gd`, `sim/sim_player.gd`, `client/game_client.gd`, `tests/inventory_test.gd`, `tests/gear_test.gd`, `tests/wire_test.gd`.

Model:

- `ItemDef` (`extends Resource`, one `.tres` per item in `data/items/`): `id`, `title`, `kind` (enum `Kind`: `WEAPON, SHIELD, RANGED, ARMOR, TRINKET, MATERIAL, BOLT, CONSUMABLE`; never a native class name), `slot` (enum: `NONE, MAIN, OFF, RANGED, HELM, CHEST, LEGS, CAPE, TRINKET, BOLTS`), `stack` (max), `rarity` (0 to 4), `weight`, `damage` (a multiplier on the attack's `AttackDef.damage` for weapons and bolts, 1.0 is the starting kit), `defense` (armor pieces: flat damage removed from each hit; a shield: extra block share), `stamina`, `icon` (Texture2D, optional), `model` (prop glTF path, optional), `prop` (the `CharacterModel.show_prop` name for a hand item). Numbers in data only.
- `Items` (static, like `Combat`): `IDS` (const `Array[StringName]`, the index is the number that travels in rolled back state; index 0 is "none"; append only, a reorder is a protocol bump), `by_id(id)` (`get` would clash with `Object.get`), `index(id)`, `def(index)`.
- `Inventory` (`RefCounted`, pure, no nodes, fully unit tested): `bag` of 32 stacks and `gear` of 10 slots (`MAIN, OFF, RANGED, HELM, CHEST, LEGS, CAPE, TRINKET_A, TRINKET_B, BOLTS`); a stack is a tiny inner class `Stack` (`id`, `count`), not a Dictionary, so types are checked. Every operation validates its arguments and returns whether it did anything, never asserts on client input: `move(from, to)` (cell numbers: 0 to 31 bag, 32 and up gear; merges on the same id with room, swaps otherwise, refuses a stack in the wrong gear slot), `split(cell, count)` (into the first empty bag cell), `equip(cell)` (to the item's slot, the old item goes to the freed bag cell; fails when nothing fits), `unequip(slot)`, `drop(cell, count)` (returns the removed stack), `add(id, count) -> int` (leftover that did not fit; stacks first, then empty cells), `sort()` (by kind, rarity high first, then id; merges stacks), `store_matching(other: Inventory)` (moves every stack whose id `other` already holds; chests in task 2), `to_dict()` and `from_dict(data)` (clamps counts to `stack`, drops unknown ids and cells out of range, never throws), `starting_kit()`.
- `Loadout` (pure): from an `Inventory` computes the small ints combat needs: `main_hand`, `off_hand`, `ranged` (item indices) and `armor` (sum of worn `defense`, clamped 0 to 255), plus `damage_scale(index)` and `damage_taken(amount, blocking)`.
- Rolled back: those four ints, a new `SimPlayer` field group `GEAR` (`main_hand`, `off_hand`, `ranged`, `armor`), appended to `STATE` and packed with the `COMBAT` group (serializers in `Wire._fill`, `uint8`). Only the server sets them; a client's prediction just continues from the server's state. The defaults are the starting kit (0 is nothing worn). `Inventories` applies intents when they arrive (the inventory is not rolled back) and keeps the four ints per player; it writes them to the `SimPlayer` in `NetworkRollback.after_process_tick` (every step, only when different, like `Spawner.update`): written before the tick loop they would be lost, because netfox restores the recorded state of the first rollback tick over them, and a resimulated tick restores older gear. No `mutate` is needed (players are recorded every tick).
- `SimPlayer` reads them: `_strike` multiplies `def.damage` by the main hand's `damage`, `_shoot` multiplies the bolt damage by the ranged item's, `_take` removes the armor's `defense` from the hit (never below a quarter of it), a blocking off hand shield adds its `defense` share to `Tuning.block_reduction`. Nothing about items is read from outside the rolled back ints.
- Server: `Inventories` node (child of `GameServer`): peer id to `Inventory`, made at hello with the starting kit (task 4 replaces the source with the client's character). RPCs in `net/net.gd`: `inventory_intent(op: int, a: int, b: int)` (`any_peer`, `reliable`; `enum Op` in `Net`: `MOVE, SPLIT, EQUIP, UNEQUIP, DROP, SORT, STORE_MATCHING`; the server takes the sender from `multiplayer.get_remote_sender_id()`, ignores peers without a player, rate limits to 30 intents a second), `inventory_changed(cells: Dictionary)` (`authority`, `reliable`; cell number to `{id, count}`, changed cells only), `inventory_snapshot(data: Dictionary)` (`authority`, `reliable`; once, after the player spawned; `Inventory.cell_dict()`). `Inventories` has no RPC calls itself: it emits `changed(peer, cells)` and `dropped(peer, stack)`, `GameServer` sends. Client: `GameClient.inventory` (an `Inventory`), `inventory_updated`, `send_intent(op, a, b)`. The client keeps a read only `ClientInventory` (the same `Inventory` class, filled from the deltas) for the panel; it never predicts moves, the server's answer is the truth. `Net.PROTOCOL_VERSION` 29.
- Starting kit: sword, wooden shield, crossbow, 20 bolts. Items to author for tests and task 2's loot: 3 weapons, 2 shields, 3 armor pieces (rarities 0 to 2), 2 trinkets, bolts, 4 materials (hide, iron scrap, bone, ember), a bandage consumable (heals; task 3's hotbar uses it).

Tests: `inventory_test.gd` (every operation, a full bag, a split of 0 or more than held, `equip` of a material, a cell out of range, `from_dict` with unknown ids and negative or huge counts, a stable sort); `gear_test.gd` (with the real `SimPlayer` as `combat_test.gd` does: a better sword changes the damage a dummy takes, armor lowers damage taken, a shield changes the block, an equip changes the rolled back ints); `wire_test.gd` (the four ints have serializers; a full player state still fits 508 bytes). Done when also `python tools/run_load_test.py` still holds 29 tps with 6 bots (numbers in the commit message).

### 2. Loot feel (Sonnet)

Files: new `sim/loot_table.gd`, `data/loot/*.tres`, `sim/world_objects.gd`, `sim/spawner.gd`, `sim/enemy_def.gd` (`loot` field), `data/enemies/*.tres`, `net/net.gd`, `net/game_server.gd`, new `client/objects_view.gd`, `shaders/loot_beam.gdshader`, `client/sounds.gd`, `client/hud.gd`, `docs/RESOURCES.md`, `tests/loot_test.gd`.

- `LootTable` (`Resource`): `entries` of `{item, weight, min, max, chance}` and `rolls`; `LootTable.roll(rng) -> Array` of stacks is pure and seeded. One `.tres` per enemy kind (`EnemyDef.loot: StringName`, empty means nothing; the dummy and the free slot have none), one for the Warden, one for the elite's chest, `chest_elite` (a guaranteed uncommon or better piece).
- `WorldObjects` (server data, not nodes; the registry task 4 saves and M58 and M67 reuse): `entries` maps an id (int, counting up, never reused) to `{kind (DROP, CHEST, GRAVE), contents (an Inventory dict, one cell for a drop), position (world), up, owner (player ID string, grave only), born (world seconds), flags}`; `add`, `remove`, `update`, `to_dict`, `from_dict` (clamps like `Inventory.from_dict`). Clients hear by reliable RPC deltas: `object_added(id, data)`, `object_removed(id)`, `object_updated(id, data)`, plus `objects_snapshot(all)` after the player spawned (next to `inventory_snapshot`). A drop nobody picks up despawns after 10 minutes (checked in `update`, 5 Hz).
- Where drops come from: `Spawner._tend` rolls the member's table the first time it sees it `DOWN` (the only place; `_dead` remembers it, so a replayed tick finds the member there and rolls nothing). Seed the roll from (world seed, camp id, member): a restart gives the same pile. The boss: `Spawner.update` also checks `world.encounters` and rolls the Warden's table once per cleared realm (memory `_boss_looted`, saved by task 4 so a restart does not drop it twice). The server stores only the landing spot (position plus a small seeded offset); the arc is drawn on clients.
- The elite's chest: `Spawner.chests(realm, world_seed)` (pure, from `points` the way camps are: one per camp whose recipe holds `barrow_elite`, 5 m behind the camp center along its facing, on walkable ground) becomes `CHEST` objects when the server starts (`WorldObjects.seed_chests`, skipped for chests already in a loaded save). It opens by intent `open_object(id)` only when its camp has no living members (`Spawner.camp_clear(unit)`) and the player is within 3 m; it hands out its table once (`flags.opened`) and stays as an open chest. Other chests come with M58.
- Pickup: materials walk over within 1.2 m of a living player (server, `WorldObjects.update`); everything else by intent `pickup(id)` (key E, `Controls` action `interact`; the client sends the id of the object its view highlights, nearest within 2.5 m). The server adds to the inventory (`Inventory.add`; a leftover stays on the ground and says "Bag full" through `Net.notice`), removes the object and sends `item_toast(id, count)`; the HUD shows "+2 Iron scrap" (`Hud.notice`).
- Look: `ObjectsView` (a child of the realm place; `Arena.shows` hides it elsewhere) draws one node per object from the deltas. Drops burst out on an arc and land (ease, a small bounce, a few particles, a thud), bob and turn slowly, glow by rarity (white, green, blue, purple, gold: rarity is the one place color is spent), rare and up add a vertical light beam (`loot_beam.gdshader`, additive, fading with height), pull toward a player within 3 m and fly into them on pickup (the view is freed when the delta says removed; the pickup sound plays then). Chests use the vendored `Chest_Wood`; check the glTF for a separate lid node before planning the open animation (else swing the whole model's top with a clipped copy, or fade to an open variant). `Sounds.library` gets `loot_drop`, `loot_pickup`, `chest_open` (Kenney files already in `assets/sounds/kenney/`, else synthesize in `tools/make_sounds.py`).
- Screenshots (`--seed=1234`, `--spawn` at an elite camp, which `Spawner.points` finds; put the command in the commit message): a drop pile in the grass, a rare beam, an opened chest. Loot feel is a stated goal of the milestone: the user's verdict goes into `docs/PLAYTEST.md`.

Tests: `loot_test.gd`: table rolls are seeded and respect min, max, chance; a kill drops once (also when `Spawner.update` runs twice on the same state); the boss drops once; a chest opens only when its camp is clear, only once, and gives the elite table; pickup adds to the inventory, leaves a leftover when the bag is full, ignores a player 10 m away; a drop expires.

### 4. Saves and graves (Opus)

Files: new `sim/save_file.gd`, `sim/world_save.gd`, `client/character_save.gd`, `sim/graves.gd` (server), `client/settings.gd` (`player_id`), `net/net.gd`, `net/game_server.gd`, `net/inventories.gd`, `sim/encounter.gd`, `sim/spawner.gd`, `sim/world_objects.gd`, `boot/main.gd`, `tests/save_test.gd`.

- `SaveFile` (static, shared by both files): `write(path, data: Dictionary) -> bool` (JSON text to `path.tmp`, flush, close, then replace `path`; `DirAccess.rename` does not replace an existing file on Windows, so move the old file to `.bak`, rename the new one in, remove the `.bak`, and test exactly that), `read(path) -> Dictionary` (empty when the file is missing; when it does not parse, or its `version` is newer than the code's, rename it to `<name>.bad-<unix time>` and return empty, never crash), `VERSION := 1` in each file and an empty `migrate(data)` hook.
- World file `user://worlds/<name>.json` (name sanitized to `[a-z0-9_-]`, `WorldSave.path(name)`): `version`, `seed`, `name`, `world_seconds` (time the server ran this world; M69 to M71 count growth in it), `flags` (written for reading, from `World.flags()`), `bosses` (realm id to `{cleared, looted}`), `cleared` (`[realm id, camp id]` to seconds left, from `Spawner.cleared_left`), `objects` (`WorldObjects.to_dict`: drops, chests with their opened state, graves), `next_object_id`. Loading: `GameServer.start` reads the file before `_world.build`; the file's `seed` wins over `--seed` (print a note). After build: `Encounter.restore_cleared()` sets `phase = CLEARED` and puts the boss slot `DOWN` as a corpse (`boss.become(warden, post, DOWN)` then `SimPlayer._mutate(boss)`, before any player is spawned, so no replay); `Spawner.restore_cleared(seconds_by_id)` maps `[realm, camp]` onto units through `_ids` and sets `_cleared_until[unit] = NetworkTime.tick + seconds * TICKRATE` (ids that no longer exist, after a layout change, are ignored); `WorldObjects.from_dict`.
- Saving: `GameServer` autosaves every 300 s (a `Timer`; building the dictionary is cheap, the write is a few KB) and on every normal exit: `_remove_player` and the timeouts that call `get_tree().quit`, and the close and predelete notifications of a dedicated server. A crash loses at most five minutes of world; the character loses seconds (below).
- Character file on the client, `user://characters/<name>.json`: `version`, `id` (the player ID), `name`, `inventory` (`Inventory.to_dict`), `junk`, later `level` and `perks` (M57). `Settings.player_id` is 16 random hex characters made on the first run and kept in `settings.cfg` (`[player] id`); the ID inside the file is what graves and the server key on. `hello(version, name, character: Dictionary, player_id: String)` replaces `hello(version, name)` (`Net.PROTOCOL_VERSION` 30). The server runs `Inventory.from_dict` (clamps, rejects unknown ids: what it cannot read starts as the starting kit) and keeps the ID. After every inventory change the server sends `Net.character(data)` (`authority`, `reliable`, at most once a second per player, and once when the player leaves); `CharacterSave` writes it (temp file, rename). The server keeps nothing per player across a restart.
- Graves (`Graves`, a server node): watches players after each tick; the first tick a player is `DEAD` for a given `respawns` value (memory keyed by peer and `respawns`, so a replayed death makes one grave) moves the whole bag (not `gear`) into a `GRAVE` object where the body fell (feet position, on the ground) and sends one `inventory_changed` and `character` update. Only the owner opens it (intent `open_object`, within 3 m) for 10 minutes of world time; then anyone can. An empty grave goes away; what does not fit the bag stays in it. XP comes with M57 (its brief says the grave also holds the XP toward the next level).
- `--world=NAME` already sets `GameServer.world_name`; with a file of that name the world continues. Without one a new world is made with `--seed` (or a random one) and saved at the first autosave.

Tests: `save_test.gd`: `SaveFile` round trip, a missing file, truncated JSON (kept as `.bad-*`, load returns empty), a newer `version`, a write over an existing file (the Windows rename), a `.tmp` left from a power cut with the real file intact; a world with the Warden cleared, two camps cleared and a drop, saved and loaded into a fresh `World` with the same seed: `Encounter.phase`, `World.flags()`, the cleared camps (seconds left within a second) and the objects match; one grave per death, opened only by its owner before 10 minutes; a hostile character (unknown ids, count 10^9, 500 cells) is clamped; if cheap, a character round trip through the real hello path in the network test (it has a bot).

## Pitfalls

- Inventory is not rolled back, combat is: an equip arrives at a tick. Apply it on the server in the tick loop and let the equipped ids travel as state, so prediction corrects itself.
- Drops must not be nodes in rollback. They are plain server data with client views.
- Never write a save in place: temp file, flush, rename.
- The character comes from the client: clamp counts and reject unknown ids so a broken file cannot crash the server, even though cheating is accepted.
- `Spawner.update` and `Encounter._rollback_tick` run again in replayed ticks. Loot, graves and saves key on memory outside rollback (`_dead`, `respawns`), or a replay pays twice.
- `Items.ids` order is wire state: append only.
- `Spawner._cleared_until` holds ticks, which restart at 0 with every server run: save seconds left, never the tick.
- The Warden's slot (`Pool0`) must be restored as a corpse before the first player is spawned, or clients see it hidden while the flag says cleared.
- Windows: `DirAccess.rename` does not replace an existing file; test the save path here.
- A chest is a world object, not a rollback node. Its camp's clear state is server memory and is lost on restart (the camp respawns after 10 minutes anyway); the chest's opened flag is what persists.
