# CLAUDE.md

`docs/PLAN.md` is the source of truth for scope, design, architecture and milestones; read it before starting work. Setup, run and check commands are in `README.md`.

The lobby (`lobby/`) and its deployment (`deploy/lobby/`) live in this repo; M8 deploys them on the gvm host.

Record every third-party asset in `docs/RESOURCES.md` (source, commit, license) when adding it.

Use Godot 4.7 (latest 4.7.x patch) and its newest features for performance and visuals (`docs/PLAN.md` §3.1). Check each engine feature against the 4.7 docs and migration guide instead of relying on older Godot 4 habits. A quick way to check that a class, constant or setting exists: a `extends SceneTree` script run with `godot --headless -s`.

Run `python tools/check.py` (lint, gdUnit4, headless network test) before calling work done. GDScript is statically typed; `enum` names must not shadow native classes (`Button` did).

Every commit is a semantic commit (`type(scope): summary`, Conventional Commits; see the `semantic-git` skill). PR titles too. Pushing to `main` publishes a release (see Release below).

- **Ranged (M3):** `SimPlayer.weapon` (`Weapon.SWORD`/`CROSSBOW`, from `PlayerControls.weapon`), actions `DRAW`/`SHOOT`, `_shoot` and `_fly_bolts`; bolts are 4 slots of packed arrays in the player's `STATE` (`bolt_pos`, `bolt_vel`, `bolt_life`, `bolt_damage`); `Combat.aim_target`, `Combat.ray` (world layer only), `Combat.enemy_on_segment`. `CameraRig.aiming` lerps to `Combat.AIM_*`, which must stay the aim geometry. `tests/ranged_test.gd`. Layers: 1 world, 2 players, 4 enemies; players collide with world and enemies, enemies with world and each other.
- **Combat (M2):** `SimPlayer` action state machine (`Action`, `action_time` in ticks, `Queued` input buffer, presses from `last_buttons`); attacks are `AttackDef` resources (`data/attacks/`, `Combat.attack(id)`, players index `Combat.PLAYER_ATTACKS`). `Combat.in_arc` for every hit. Enemies (`sim/enemy.gd`, `TrainingDummy`) are in group `enemies` with a stable `index` (bit in the player's `swing_hits`); players check enemy swings in `_defend` during their own tick and call `NetworkRollback.mutate(enemy)` after changing one (`SimPlayer._mutate`). Views pose `CharacterModel` (`client/character_model.gd`) from state with `play_timed`/`loop` and attach props by name (`show_prop`). `tests/combat_test.gd` covers hits, combo, stamina, roll, block, parry, riposte, death; rerun after changing numbers. Every rolled back variable must be in the node's `STATE` list, or rollback silently keeps the wrong value.
- **Gravity (M1):** `sim/layout.gd` holds the zones, asteroid and jump pads (data both sides share); `Gravity.sample`/`zone_at` (`sim/gravity.gd`, `sim/gravity_zone.gd`); `SimPlayer.step` launches from `Layout.pad_at` on jump; `SimPlayer.place(feet)` stands a body along local gravity (use it for every spawn or teleport, or the capsule starts inside the surface). `tests/asteroid_test.gd` walks around the asteroid and flies both pads with the real arena collision; rerun it after changing layout or movement numbers.
- **Boot:** `scripts/boot/main.gd` picks the role from args. No args: main menu; `--solo`: spawns `--server --solo` on a free port and joins it (solo exits when its player leaves). `--connect`, `--bot`, `--screenshot=PATH` (saves a PNG after 4 s and quits; use it to check visuals), `--look=YAW,PITCH` (start camera, degrees), `--spawn=X,Y,Z` (server spawn point; solo passes it on), e.g. `--spawn=40,68.1,0` is the asteroid's top, `--spawn=4,0,-7.6` stands at the swinging dummy; `--delay=S` (screenshot wait), `--graphics=low|medium|high|ultra`, `--frames=N` (a burst 50 ms apart), `--bot --bot-plan=shoot` (a windowed bot that aims along `--look` and fires full draws, for screenshots). `STELLAMORTIS_SERVER_STATS=1` makes a server print its tick loop time every second (headless with one bot: 1.6 ms average; a solo server next to an uncapped windowed client reads up to 10 ms from CPU contention). Fake latency: `tools/lag_proxy.py` (UDP proxy, `dev.py --lag=MS`, the network test uses 100 ms + 20 ms jitter).
- **Netcode:** netfox (`game/addons/netfox`, `netfox.internals`, installed by `tools/install.py` from `NETFOX_COMMIT`, gitignored; autoloads and `[netfox]` settings live in `project.godot` because the editor plugin never runs headless). Tick 30 Hz, `sync_to_physics`. Read the netfox docs (https://foxssake.github.io/netfox/, rollback caveats first) before adding rollback state. `SimPlayer.networked(peer)` adds `Controls` (input, owned by the peer), `Rollback` (`RollbackSynchronizer`, state `SimPlayer.STATE`) and on clients `Interpolator`. `sim/world.gd` (`/root/Main/Game/World`, same path on both sides) holds the arena, `Players` and the `MultiplayerSpawner`. `net/net.gd` keeps only our RPCs (`Net.PROTOCOL_VERSION`, bump on change, also when netfox state or input changes).
- **Movement:** `sim/sim_player.gd`. Players move in the plane of `up`, which follows `Gravity.sample` (`sim/gravity.gd`, constant until M1); `ref_forward` is carried along when `up` turns, and input yaw and the camera yaw (`client/camera_rig.gd`) are measured from it. `grounded` is our own floor flag, part of the rolled back state. Players do not collide with each other (layers: 1 world, 2 players). Numbers in `data/tuning.tres` (`Tuning.data()`).
- **Arena:** `sim/arena.gd`, built in code from `Layout`; collision on both sides, meshes, sun, space sky shader, environment (AgX, SSAO, SSIL, glow, distance fog, volumetric fog only from the zones' `FogVolume`s), zone particles and pads on clients only.
- **Release:** `.github/workflows/release.yml` on every push to `main` (and by hand): check, export per platform on its own runner (`tools/export.py`, presets in `game/export_presets.cfg`), artifacts kept 3 days (`ARTIFACT_DAYS`), then a GitHub Release `v<VERSION>.<patch>` with three zips. Every milestone is a minor version: the commit that finishes a milestone raises `VERSION`'s minor by one (`0.16` after M15; the next finished milestone, whichever it is, makes `0.17`), since milestones no longer finish in order; the milestone's number goes in its `docs/milestones/DONE.md` row; pushes in between are patches (next free patch from the existing tags). Exported builds spawn themselves as the solo server (`OS.has_feature("template")` in `main.gd`).
- **Physics:** Jolt, 30 ticks per second, Godot physics interpolation off (netfox `TickInterpolator` instead). Renderer Forward+ (Vulkan on Linux), SMAA.
